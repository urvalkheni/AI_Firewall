Abstract

1

8

As Large Language Model (LLM) agents are granted autonomous
access to external environments via tool execution APIs and standardized protocols like the Model Context Protocol (MCP), they
become susceptible to indirect prompt injection, tool poisoning, and
unauthorized capability execution. Existing defenses rely heavily on
model alignment, prompt filtering, or custom language interpreters;
however, these techniques either fail against adaptive attacks or
lack binding authorization mechanisms when human-in-the-loop
oversight is required.
This paper presents AI Firewall, a shared, risk-based authorization gateway that mediates tool invocations across heterogeneous
agent adapters prior to downstream execution. AI Firewall enforces
a tripartite security protocol: (1) deterministic transformation of
heterogeneous tool proposals into canonical action identities using
RFC 8785 JSON Canonicalization and SHA-256 digests; (2) declarative policy evaluation that computes risk scores and mandates cryptographic Ed25519 approval envelopes bound to the exact canonical
action digest; and (3) transactional lifecycle fencing on SQLite with
monotonic worker epochs that prevents approval replay, parameter
tampering, and post-timeout execution races.
We evaluate AI Firewall through an empirical evaluation across
a formal 46-scenario security benchmark (31 consequential attacks
and 15 legitimate tasks), supported by a comprehensive 107-test
regression suite. In the evaluated benchmark suite, AI Firewall
successfully blocked 31 of 31 consequential attacks (100.0% observed, Clopper–Pearson 95% exact binomial confidence interval
[88.8%, 100.0%]) while executing 15 of 15 legitimate tasks without false denials (100.0% observed utility, 95% CI [78.2%, 100.0%]).
Under a thread-bounded connection registry optimization, median authorization overhead is reduced by 81.29% (from 3.0153 ms
to 0.5643 ms), with P99 tail latency dropping by 95.97% (from
24.0348 ms to 0.9679 ms) and batch throughput scaling to 1,716.4
operations per second. We verify protocol interoperability across
MCP stdio child processes and simulated LangGraph-style workflows, and formalize the downstream execution boundary where
tool idempotency is required to guarantee end-to-end execution
safety upon network timeouts.

Autonomous AI agents powered by Large Language Models (LLMs)
are transitioning from isolated chat interfaces into proactive systems that invoke external APIs, query relational databases, alter
file systems, and execute code on behalf of human users [? ? ]. To
facilitate tool interoperability, industry architectures have rapidly
converged on shared protocols such as Anthropic’s Model Context
Protocol (MCP) [? ] and agent orchestration frameworks such as
LangChain and LangGraph.
However, giving LLMs the autonomy to execute external tools
introduces severe security risks. When an agent processes untrusted
external data—such as web pages, email bodies, or database query
results—an adversary can embed adversarial instructions known as
indirect prompt injection (IPI) [? ]. These injected instructions hijack
the model’s reasoning loop, causing it to invoke consequential tools
without user knowledge, exfiltrate confidential data, or destroy
critical infrastructure.
Recent security literature has proposed diverse countermeasures.
DataSentinel [? ] explores game-theoretic prompt filtering; however,
purely text-based classifiers suffer from false positives and remain
vulnerable to adaptive prompt evasions. IsolateGPT [? ] isolates
application execution contexts, and CaMeL [? ] enforces capabilitybased information flow tracking within a custom Python interpreter.
Similarly, Progent [? ] uses domain-specific languages and SMT
solvers to enforce monotonic privilege narrowing.
Despite these advancements, an architectural vulnerability remains at the boundary between agent decision-making and external tool dispatch: the absence of a shared, protocol-agnostic
authorization gateway that cryptographically binds human
approval to the exact tool call being executed. When current
frameworks implement human-in-the-loop (HITL) checkpoints:

Authorization

While CaMeL and Progent provide compelling defenses, they require either running code in a bespoke Python interpreter or deeply
modifying the internal agent runtime loop. They do not address
environments where tool execution occurs across distributed protocols (such as MCP over stdio or SSE), nor do they provide cryptographic verification when consequential actions mandate human
sign-off. Furthermore, they do not account for concurrency races,
stale worker fencing, or downstream retry semantics. AI Firewall
addresses this gap by operating as an external, protocol-aware

Assets and Adversary Capabilities

We consider an environment where an AI agent interacts with
external resources (filesystems, databases, APIs) via tools (Figure 3).
• Adversary Capabilities: The adversary can inject arbitrary natural language into any untrusted data source retrieved by the agent. The adversary can influence tool call

approval and execution, replay intercepted approvals, and
manipulate concurrency timing.
• Untrusted Components: The LLM reasoning core, prompt

• Trusted Computing Base (TCB): The AI Firewall gateway, its local SQLite database, the human reviewer’s private key, and the gateway’s cryptographic key registry are
trusted.

7.1 Defense-in-Depth vs. Model Alignment

551

A recurring theme in recent AI safety research is that LLM prompt
alignment is fundamentally non-robust [? ? ]. Adversaries continuously discover jailbreaks, multi-lingual encodings, and promptinjection perturbations that bypass system prompts. AI Firewall
treats the entire LLM reasoning pipeline as untrusted, enforcing
security invariants at the deterministic network boundary. Even if
an agent’s internal reasoning is compromised, it cannot produce
valid cryptographic signatures over unauthorized canonical digests.

Limitations and Threats to Validity

Conclusion and Future Work

We presented AI Firewall, a shared, risk-based authorization gateway for autonomous AI agents. By coupling RFC 8785 canonical
action identity with Ed25519 cryptographic approval envelopes,
AI Firewall eliminates parameter tampering, approval substitution,
and replay attacks across heterogeneous agent adapters. ACIDcompliant SQLite lifecycle management with monotonic dispatch
epoch fencing guarantees safe mutual exclusion and fail-closed
crash recovery. Through a manager-owned thread connection registry, the gateway achieves sub-millisecond median latency (0.56 ms)
and 1,716 ops/sec throughput, demonstrating that rigorous runtime
authorization imposes negligible overhead on AI agent execution.

(1) Synthetic Evaluation Suite: While our 46-scenario benchmark and 107 regression tests cover adversarial parameter
mutations, timing races, and protocol errors, they represent
a curated synthetic test suite rather than a live multi-tenant
production deployment.
(2) Third-Party Package Absences: The official mcp and
langgraph pip packages were not installed in the test environment. While protocol framing was validated via real OS
subprocess stdio pipes, testing with official SDK runtime
classes remains future work.
